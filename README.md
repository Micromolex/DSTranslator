# DeepSeek Translate — 中文 ↔ Русский

Android-приложение для перевода **русский ⇄ китайский (путунхуа)** через ИИ DeepSeek.
Ключ API **не входит в APK**: при первом запуске приложение попросит вставить свой
ключ DeepSeek, он сохраняется только на устройстве.

## Режимы

| Вкладка | Что делает |
|---|---|
| **Текст** | Текстовый перевод RU ⇄ ZH, потоковый вывод, **голосовой ввод**, озвучка, копирование. Старый перевод не исчезает, пока не придёт новый; дописанный текст переводится только хвостом |
| **Два экрана** | Телефон кладётся между собеседниками: верхняя половина перевёрнута на 180° и обращена к человеку напротив, нижняя — к владельцу телефона. **Перевод уезжает на половину собеседника**: сказал по-русски — китайский текст появляется сверху. Своя речь видна у говорящего мелко, перевод — крупно у читающего. Крупный шрифт |
| **Авто** | Автодиалог по ролям: **одна непрерывная запись**, микрофон не выключается между фразами. Распознавание **потоковое** во всех трёх режимах: запись сразу пишется в кольцевой буфер, язык определяется по первым ~1.6 с (Whisper tiny), затем русская или китайская streaming-модель zipformer получает буфер **с самого начала реплики** — первые слова не теряются. Промежуточный текст показывается **серым сверху под чипами и не переводится**; перевод уходит в историю только по паузе (endpoint). Список переводов **сам прокручивается вниз** по мере поступления текста. Сверху — чипы (**Авто / только RU / только ZH**) и кнопка очистки. **«только RU» / «только ZH» используют те же модели**: в русском режиме — только русская модель, в китайском — только китайская (без LID, скачивается ~25 МБ) и показывают два окна: сверху оригинал, снизу перевод, прокрутка общая |
| **Настройки** | Модель (`deepseek-chat` / `deepseek-reasoner`), автоозвучка, учёт контекста, **потоковые модели распознавания** (RU + ZH + LID, ~150 МБ, скачиваются отдельно; устаревший локальный движок Qwen3-ASR удалён), «О приложении / Правовая информация» |

## Что нового в v1.6.10

- **«Авто» переведён на потоковое распознавание sherpa-onnx.** Вместо offline-модели
  с VAD-нарезкой — streaming zipformer: русский
  `streaming-zipformer-small-ru-vosk-int8` и китайский `streaming-zipformer-zh-14M`,
  оба int8. Язык определяет **Whisper tiny** (SpokenLanguageIdentification) по первым
  ~1.6 секундам речи.
- **Первые секунды не теряются.** Микрофон сразу пишет в кольцевой буфер в памяти.
  LID работает в отдельной корутине и не блокирует запись. Когда язык определён,
  streaming-модель получает **весь буфер с начала реплики**, а затем — аудио
  в реальном времени.
- **Перевод только по endpoint.** Промежуточный текст streaming-модели выводится
  серым и не переводится. По паузе (1.2 с тишины) приходит final: серая строка
  стирается, в историю добавляется карточка с переводом, запись продолжается.
- **Смена языка на ходу.** LID перезапускается на каждой новой реплике; при смене
  языка старая streaming-модель выгружается, новая получает буфер с начала реплики.
- **Модели скачиваются отдельно** (в настройках, ~150 МБ: RU + ZH + LID), в APK их нет.
  Без них обычный «Авто» не стартует и предлагает скачать; «только RU» / «только ZH»
  работают как раньше.

## Что нового в v1.8.0

- **Лимит распознавания — 10 секунд на реплику.** Раньше длинная речь без пауз
  уходила в распознавание целиком, и перевода не было, пока человек не замолчит

  `SpeechRecognizer.stopListening()` закрывает её штатно, а если сервис

  останавливается: следующая фраза начинается сразу. В локальном движке тот же

  пяти столбиков (микрофон слушает), текст по словам — последнее распознанное

  лимита «3 / 10 с». Работает в «Тексте» при голосовом вводе и в «Авто».

  убраны: оригинал идёт строкой мельче, под ним перевод — крупно и жирно, без
  пузырей, фонов и кнопок (`MonoTranscript` в `AutoDialogScreen.kt`). Обычный

- **Автоповорот экрана отключён.** В `AndroidManifest.xml` у Activity стоит
  `android:screenOrientation="portrait"` — при повороте планшета интерфейс не
  пересоздаётся и запись не сбрасывается.

## Что нового в v1.7.0

### Исправлен авторежим

- **Письменность важнее ответа распознавателя.** В ветке автоопределения язык берётся
  из текста (`LangDetect.detect`), а не из `DETECTED_LANGUAGE`: вендорский движок
  сообщает язык **сеанса**, а не фразы. Из-за этого китайская фраза помечалась русской,
  уходила в промпт RU→ZH и возвращалась без перевода (правило «если это уже китайский,
  верни как есть»). Теперь иероглифы → сторона ZH, кириллица → RU.
- **Ложные маркеры модели больше не ломают перевод.** Правила про `[[!]]` / `[[SKIP]]`
  отправляются только когда письменность НЕ совпала с ожидаемой стороной. Для обычного
  текста маркер снимается без смены языка и без уведомления «Похоже, говорили на…» —
  раньше фраза «автоперевод сломался» помечалась как транслитерация китайского.
- **Ложный `[[SKIP]]`** на нормальном тексте больше не удаляет карточку: фраза
  переводится повторно, уже без правил про маркеры.
- **Чипы «только RU» / «только ZH» сбрасывают накопленные догадки** распознавателя
  (`detectedLanguage`, `detectionSeen`, `lastSessionWasSilent`) и перезапускают сеанс
  на выбранном языке, в том числе если запись была на паузе.
- **Переключение языка при неудачном распознавании** больше не блокируется флагом
  `detectionSeen` — раньше на устройствах, где движок «нашёл» язык один раз,
  китайская речь переставала распознаваться вообще.

### Новое: локальное распознавание Qwen3-ASR (шаг 1)

> ⚠️ **Удалено в v1.6.12.** Локальный движок Qwen3-ASR и его модель больше не
> входят в приложение; ниже — историческое описание v1.7.0.

- В настройках появился выбор **движка распознавания**: «Системный» (как было) и
  «Локальный (Qwen3-ASR)». Локальный понимает русский и китайский **одной моделью**,
  включая смешанную речь, и работает без интернета.
- Модель **не входит в APK**: качается при первом включении (~941 МБ, кнопка «Скачать
  модель»), хранится в `filesDir/models/qwen3-asr`, докачивается после обрыва
  (HTTP Range), удаляется одной кнопкой.
- Движок: sherpa-onnx 1.13.8 (`app/libs/sherpa-onnx-1.13.8.aar`) + Silero VAD
  (`assets/silero_vad.onnx`). Аудио: 16 кГц моно → VAD режет по паузам →
  offline-декод Qwen3-ASR. Партиалов нет: распознаём по концу фразы.
- Потокобезопасность: звук и декодирование — в отдельных потоках, очередь сегментов
  не даёт декодеру отставать на минуты; при `OutOfMemoryError` показывается понятная
  ошибка вместо падения.
- **APK вырос до ~84 МБ** (нативные библиотеки sherpa-onnx + onnxruntime под arm64/armv7).

> ⚠️ Локальный движок включается по желанию: по умолчанию остаётся системный.
> Первый запуск локального движка занимает несколько секунд (загрузка ~1 ГБ весов
> в память). На устройствах с 4 ГБ RAM возможен OOM — об этом честно написано в UI.

  превращается в «Пусто → Перевод…».

  новый хвост, а готовая часть остаётся. Не переводим одно и то же по десять раз.
  Разбиение на предложения — `data/TextSplit.kt` (понимает «3.5», «т.е.», «...»
  и китайские точки без пробелов), проверено 15 кейсами на JVM.
- **«Текст»: голосовой ввод.** Кнопка с микрофоном рядом с «Перевести»: речь
  распознаётся и дописывается в поле ввода, после финальной фразы перевод
  запускается сам. Уход с вкладки глушит микрофон.

## Что нового в v1.8

**Главное: китайская речь больше не принимается за русскую.**

Скриншоты показали корень проблемы. Распознаватель в режиме `ru-RU` **слышит**
китайский, но записывает его русскими буквами: «Нихао», «мехама». Проверка по
письменности видит кириллицу и считает это нормальным русским — поэтому язык
никогда не переключался, а в карточки попадала бессмыслица.

Отличить транслитерацию от настоящей речи по буквам нельзя, а модель — может.
Теперь в промпте авторежима два маркера:

| Маркер | Что значит | Что делает приложение |
|---|---|---|
| `[[!]]` | смысл транслитерации понятен, дальше идёт перевод | **фраза сохраняется** (Нихао → 你好), распознавание переключается на другой язык |
| `[[SKIP]]` | смысл непонятен | мусорная карточка убирается, распознавание переключается |

Маркеры не видны: пока текст — префикс маркера, ничего не показывается.
Появляется строка-подсказка «Похоже, говорили на 中文 — переключаю распознавание».

## Что нового в v1.5

### Авторежим: фразы больше не теряются

- **Переключение по паузам.** Тишина после принятой реплики один раз меняет

## Что нового в v1.4

- **Починено качество распознавания.** В v1.3 `EXTRA_LANGUAGE` был убран целиком
  ради автоопределения — на устройствах без поддержки детекта это ломало
  распознавание («привет» → «.»). Теперь `EXTRA_LANGUAGE` передаётся всегда,
  а детект и переключение остаются как бонус, если распознаватель их умеет.
- **Авторежим переписан на чередование с проверкой.** Работает даже там, где
  автоопределения нет:
  - сеанс идёт на текущем языке;
  - если текст пришёл на этом языке (`LangDetect.matches`) — реплика принята,
    **язык не меняется**, поэтому один человек может говорить сколько угодно
    фраз подряд;
  - если распознаватель **услышал речь** (`onBeginningOfSpeech`), но текст
    вышел на другом языке или не вышел вовсе — значит, заговорил второй
    собеседник: мусорный черновик отбрасывается, следующий сеанс идёт на
    другом языке;
  - тишина в комнате язык НЕ переключает.
- **Фильтр мусора.** Реплики без букв («.», «…») больше не уходят в перевод,
  а «чужая» письменность (иероглифы при русском сеансе и наоборот) отсекается.
- Ручные режимы `🇷🇺 только RU` / `🇨🇳 только ZH` остаются как аварийный вариант.

### Ограничение

Если распознаватель устройства не поддерживает `EXTRA_ENABLE_LANGUAGE_DETECTION`,
полностью «бесшовное» определение невозможно: при смене говорящего теряется
первый короткий фрагмент его фразы — распознаватель «поймёт» это только по
факту речи на другом языке и переключится на следующем сеансе.

## Что нового в v1.3

- **Убрано «пиликанье» микрофона.** На время прослушивания глушатся
  `STREAM_SYSTEM`, `STREAM_NOTIFICATION` и `STREAM_MUSIC` (системный «динь»
  распознавателя), музыка поднимается обратно прямо перед TTS. Добавлено
  разрешение `MODIFY_AUDIO_SETTINGS`.
- **Починено автоопределение языка.** Причина была в `EXTRA_LANGUAGE`: если он
  задан, распознаватель не определяет язык сам. Теперь в авторежиме он не
  передаётся вообще, включены `EXTRA_ENABLE_LANGUAGE_DETECTION` и
  `EXTRA_ENABLE_LANGUAGE_SWITCH` (`MAX_SWITCHES=100`).
- **Запись не рвётся.** Пауза перед перезапуском сеанса в авторежиме = 0 мс,
  сеансы удлинены (тишина 2.5–3 с), поэтому паузы внутри разговора больше не
  рассекают фразу.
- **Никаких предположений о следующем говорящем.** Язык сеанса больше не
  переключается «на второго собеседника»: на Android 14+ решает распознаватель,
  на старых версиях язык подтягивается к последней реплике.
- **Аварийный ручной переключатель** на экране «Авто»: `Авто` / `🇷🇺 только RU` /
  `🇨🇳 только ZH` — на случай, если распознаватель устройства не умеет автоопределение.

## Что нового в v1.2

- **«Два экрана»:** перевод показывается собеседнику на его половине
  (`SideState.incoming`), а не на стороне говорящего. Половина показывает либо
  свою распознаваемую речь, либо перевод чужой фразы + её оригинал мелким шрифтом.
- **«Авто»:** убраны постоянные перезапуски распознавателя. Один сеанс записи,
  переключение языка внутри сеанса через `EXTRA_ENABLE_LANGUAGE_SWITCH` и
  определение через `SpeechRecognizer.DETECTED_LANGUAGE` (API 34+).
- **«Авто»:** убрана логика «следующая реплика — от второго собеседника».
  Язык следующего сеанса = язык последнего говорящего, поэтому один человек
  может говорить несколько раз подряд.

## Что было в v1.1

- **Запись больше не зацикливается.** Микрофон глушится *до* старта перевода:
  в режимах «Два экрана» и «Текст» распознавание останавливается сразу после
  финальной фразы (`stopAfterFinal`), только потом идёт перевод и озвучка.
- **Воспроизведение приостанавливает запись.** `SpeechController.speak()` переводит
  распознавание в паузу и возобновляет его по событию `onDone` от TTS —
  приложение не слышит само себя. Работает и в «Авто» при нажатии кнопки прослушивания.
- **Защита от дублей.** Одинаковая финальная фраза, пришедшая повторно в течение 4 секунд,
  не создаёт новую карточку и не запускает перевод заново.
- **API-ключ больше не вшит в код.** С v1.6.14 ключ вводится в окне
  «Ключ DeepSeek API» и хранится только на устройстве (`Prefs.apiKey`).

## Сборка

Нужен **JDK 17**: с Java 25 из Android Studio сборка падает, а портативный JDK уже
лежит в проекте — `.tooling/jdk17/`.

Сначала бинарные зависимости (AAR sherpa-onnx 47.8 МБ не лежит в репозитории):
скрипт `tools/fetch-deps.mjs` качает `app/libs/sherpa-onnx-1.13.8.aar`,
докачивая после обрыва.

```powershell
node tools\fetch-deps.mjs

$env:ANDROID_HOME="D:\Android\Sdk"
$env:JAVA_HOME="$PWD\.tooling\jdk17\<распакованная-папка>"
$env:GRADLE_USER_HOME="$PWD\.tooling\gradle-home"
.\gradlew.bat assembleRelease
```

APK: `app\build\outputs\apk\release\app-release.apk` (готовые копии — `dist\`).
Подпись — релизный ключ из `keystore.properties`. Выпуск обновления — `docs/UPDATES.md`.

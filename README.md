# DeepSeek Translate — 中文 ↔ Русский

Android-приложение для перевода **русский ⇄ китайский (путунхуа)** через ИИ DeepSeek.
Ключ API **не входит в APK**: при первом запуске приложение попросит вставить свой
ключ DeepSeek, он сохраняется только на устройстве.

## Режимы

| Вкладка | Что делает |
|---|---|
| **Текст** | Текстовый перевод RU ⇄ ZH, потоковый вывод, **голосовой ввод**, озвучка, копирование. Старый перевод не исчезает, пока не придёт новый; дописанный текст переводится только хвостом |
| **Два экрана** | Телефон кладётся между собеседниками: верхняя половина перевёрнута на 180° и обращена к человеку напротив, нижняя — к владельцу телефона. **Перевод уезжает на половину собеседника**: сказал по-русски — китайский текст появляется сверху. Своя речь видна у говорящего мелко, перевод — крупно у читающего. Крупный шрифт |
| **Авто** | Автодиалог по ролям: **одна непрерывная запись**, микрофон не выключается между фразами. Запись сразу пишется в кольцевой буфер, язык определяется по **1.8 с** речи без пауз (Whisper tiny, int8, 2 потока). Дальше **обе языковые модели — потоковые zipformer'ы** (русская `small-ru-vosk` и китайская `zh-14M`, int8): буфер **с самого начала реплики** уходит модели, поэтому первые слова не теряются, а промежуточный текст появляется **прямо во время речи** серой плашкой-субтитрами под чипами и **не переводится**. Перевод уходит в историю только по паузе (endpoint 1.2/2.4 с). Список переводов **сам прокручивается вниз** по мере поступления текста. Сверху — чипы (**Авто / только RU / только ZH**) и кнопка очистки. **«только RU» / «только ZH» используют те же модели**: в русском режиме — только zipformer (~29 МБ), в китайском — только zipformer (~25 МБ, без LID) и показывают два окна: сверху оригинал (**40 %** высоты), снизу перевод (**60 %**), прокрутка общая |
| **Настройки** | Модель (`deepseek-chat` / `deepseek-reasoner`), автоозвучка, учёт контекста, **локальные модели распознавания** (RU + ZH + LID, **~150 МБ**, скачиваются отдельно; устаревший локальный движок Qwen3-ASR и офлайн-модель GigaAM удалены), «О приложении / Правовая информация» |

## Поверх других приложений

Два способа перевести текст, **не уходя из чужого приложения** (WeChat, браузер, заметки):

| Способ | Как выглядит | Что нужно |
|---|---|---|
| **Пузырь «文A»** | Маленькая иконка «文A» поверх любых приложений. Перетаскивается и **прилипает к краю экрана**; тап открывает компактное окно (не выше 60 % экрана, с прокруткой): поле ввода → «Перевести» → результат, маленькие «Вставить» / «Копировать» / «Закрыть». «Вставить» шлёт `ACTION_PASTE` прямо в открытое поле другого приложения и закрывает окно пузыря | Разрешение **«Поверх других приложений»** (включается в настройках). Для вставки — служба спец. возможностей **«Вставка перевода»**; без неё перевод копируется в буфер и открываются спец. возможности |
| **Меню «Перевести»** | Выделите текст в любом приложении → меню выделения (⋮) → **«Перевести»**. Поверх приложения появляется компактная карточка с переводом и кнопками **«Заменить текст» / «Скопировать» / «Закрыть»**. Главный экран переводчика не открывается | Ничего: пункт меню появляется сам (Action `PROCESS_TEXT` + `text/plain`), приложению не нужны разрешения |

Оба окна ходят в DeepSeek потоково: перевод дописывается на экране по мере генерации,
язык определяется по письменности (кириллица → RU, иероглифы → ZH).

В приложении этот текст показывается в двух местах:

| Где | Как |
|---|---|
| **Настройки → «О приложении / Правовая информация»** | Отдельный экран с текстом (один TextView с переносами строк) и кнопкой возврата |
| **Первый запуск** | Диалог с тем же текстом и кнопкой «Я согласен». Без согласия приложение не работает: закрытие окна (в том числе системной кнопкой «Назад») показывает предупреждение с выбором — принять условия или закрыть приложение |

Флаг согласия хранится в `SharedPreferences` (`ds_translate` → `legal_accepted`),
поэтому диалог показывается один раз.

## Что нового в v1.6.25

- **Служба спец. возможностей больше не падает.** Вся работа с событиями и
  вставкой обёрнута в `try/catch`: «Сервис работает некорректно» больше не
  появляется, если узел поля уже уничтожен или приложение успело перестроить
  дерево. Если активного поля нет или приложение отклонило `ACTION_PASTE`,
  служба пробует резервный `ACTION_SET_TEXT`, а текст оставляет в буфере
  и подсказывает: «Текст скопирован. Вставьте вручную».
- **Настройки службы.** `canRetrieveWindowContent=true` в XML-конфиге,
  в рантайме дополнительно подтверждаются события фокуса, смены **выделения**
  (`TYPE_VIEW_TEXT_SELECTION_CHANGED`) и окна — часть приложений не шлёт
  `TYPE_VIEW_FOCUSED`, но присылает смену выделения.
- **Пузырь: «Вставить из буфера».** Под полем ввода появилась кнопка 📋:
  текст из буфера подставляется в поле и сразу уходит на перевод — без лишнего
  нажатия «Перевести».
- **Пузырь: быстрый переход в «Авто».** Кнопка **↗ Авто** закрывает окно,
  поднимает приложение на передний план и сразу открывает вкладку «Авто»
  (`Intent` extra `OPEN_TAB=AUTO`, `launchMode="singleTop"` + `onNewIntent`).
- **Стартовая вкладка — «Текст».** Холодный старт всегда открывает «Текст»;
  выбранная вкладка больше не сбрасывается при возврате из фона и при
  пересоздании Activity (`rememberSaveable`).

## Что нового в v1.6.24

- **Пузырь стал маленьким и аккуратным.** Вместо синего круга «译» — иконка
  **«文A»** 40 dp. Она перетаскивается и после отпускания **прилипает к
  ближайшему краю** экрана; служба по-прежнему показывает ровно один пузырь.
- **Компактное окно перевода.** Заголовок «Перевод-пузырь» убран, отступы
  уменьшены. Карточка со скруглениями не выше **60 % высоты экрана**, длинный
  перевод прокручивается внутри (`ScrollView`), короткий не растягивает окно.
  «Вставить», «Копировать» и «Закрыть» — маленькие текстовые кнопки.
- **«Вставить» действительно вставляет.** Служба спец. возможностей запоминает
  чужое поле ввода, кладёт перевод в буфер и отправляет в поле
  **`ACTION_PASTE`** (как системное «Вставить»); `ACTION_SET_TEXT` остался
  резервом. Окно пузыря закрывается до вставки, фокус возвращается в чат, а
  вставка повторяется 2–3 раза, если система ещё не вернула фокус. Если служба
  выключена — перевод копируется и открываются спец. возможности.
- **Меню «Перевести» починено.** В `<intent-filter>` добавлен
  `text/plain` — без него системное меню выделения не показывало пункт и не
  передавало текст. `ProcessTextActivity` теперь `AppCompatActivity`
  (корректная работа с `Theme.AppCompat.Dialog`), текст читается и как
  `CharSequence`, и как `Spanned`, окно закрывается тапом мимо.
- **Обратный перевод в «Тексте».** Под переводом появилась кнопка **🔄**:
  текущий перевод уходит в ИИ с запросом обратного перевода (ZH → RU или
  RU → ZH) **без истории диалога**, поэтому основной контекст не сбивается.
  Результат — маленький серый полупрозрачный блок курсивом с префиксом
  «Обратный перевод (проверка):»; повторное нажатие скрывает его.

## Что нового в v1.6.23

- **Плавающий пузырь «译».** Кружок поверх других приложений (`SYSTEM_ALERT_WINDOW`,
  отдельная foreground-служба, тип `specialUse`) можно перетаскивать. Тап открывает
  компактное окно: поле ввода, «Перевести», живой потоковый перевод, «Вставить» и
  «Копировать». «Вставить» записывает перевод прямо в сфокусированное поле чужого
  приложения через службу спец. возможностей (если она выключена — текст копируется
  в буфер). Включается тумблером в настройках, там же кнопка спец. возможностей.
- **«Перевести» в меню выделения текста.** Новый `ProcessTextActivity`
  (`ACTION_PROCESS_TEXT`) с темой `Theme.AppCompat.Dialog`: окно открывается
  **поверх текущего приложения** компактной карточкой, фон затемнён, переключения
  на главный экран переводчика нет. Выделенный текст сразу уходит в DeepSeek,
  показывается индикатор, затем перевод; кнопки «Заменить текст» (возврат через
  `setResult`), «Скопировать» и «Закрыть».
- Фоновый заслон (`ApiGuard`) научен отличать окна-переводчики от «забытых»
  фоновых запросов: пузырь и окно PROCESS_TEXT открывают короткую внешнюю сессию,
  и только на её время запросы к API разрешены.

## Что нового в v1.6.22

- **Русская речь распознаётся потоково.** Вместо офлайн-модели GigaAM v3
  (она не умела отдавать промежуточный текст) в «Авто» и «только RU» работает
  потоковая `sherpa-onnx-streaming-zipformer-small-ru-vosk-int8-2025-08-16`
  (`OnlineRecognizer`, int8, `models/streaming/ru`, ~29 МБ). Промежуточный
  текст появляется на экране **прямо во время речи** — серой плашкой-субтитрами
  под чипами; в DeepSeek уходит **только финальный текст** по endpoint, как и
  раньше.
- **Набор моделей стал легче:** RU ~29 МБ + ZH ~25 МБ + LID ~98 МБ =
  **~150 МБ** вместо ~454 МБ. Прежняя офлайн-папка `models/offline` (~326 МБ)
  удаляется при первом запуске автоматически.
- **Компактные плашки.** Шапка карточки плоская: название языка 12 sp, мелкий
  флаг, отступы ужаты. Воспроизведение — отдельными маленькими динамиками
  (иконка 17 dp) для оригинала и перевода, а основной текст занимает почти всю
  высоту карточки (перевод 26 sp Bold).
- **Пропорции 40/60 в ручных режимах.** «только RU» и «только ZH»: окно
  оригинала — 40 % высоты, окно перевода — 60 %, чтобы длинный перевод
  читался без постоянной прокрутки. В «Авто» реплики идут лентой карточек,
  пропорции прежние.
- **Пунктуация:** потоковая zipformer-модель отдаёт текст без знаков препинания
  и заглавных букв — это плата за живой партиал; сравнить качество на живой
  речи и при необходимости вернуть более крупную модель.

## Что нового в v1.6.21

- **«Авто» больше не путает языки.** Окно LID увеличено с 0.8 до **1.8 с**
  речи (повторные попытки — до 2.6 с), причём окно считается по речи, а не по
  времени с начала реплики: хвостовая тишина больше не разбавляет фонетику.
  Русская речь снова идёт в GigaAM (`models/offline/ru`, `OfflineRecognizer`,
  `nemo_transducer`), китайская — в streaming-zipformer
  (`models/streaming/zh`); выбор модели подтверждается явной записью
  `Using model:` в Logcat.
- **Смена языка очищает буфер.** При решении LID старый поток, партиал и
  счётчики VAD сбрасываются до загрузки новой модели, поэтому обрывки русской
  речи не склеиваются с китайскими иероглифами (и наоборот).
- **Перевод появляется всегда.** Финальный текст сразу уходит в DeepSeek
  (Logcat: `Sending to API: …`). Если модель пометила фразу `[[SKIP]]`,
  карточка больше не исчезает — выполняется повторный перевод без маркеров;
  пустой ответ показывает причину вместо вечного «…».
- **Диагностика в Logcat:** `adb logcat -s StreamingASR TranslateVM` —
  `LID detected`, `LID switch`, `Using model`, `Final`, `Sending to API`.

## Что нового в v1.6.17

- **Проверка размера при скачивании моделей стала обязательной.** Для ответа
  `200` берётся `Content-Length`, для `206` — общий размер из `Content-Range`;
  он должен совпасть с ожидаемым размером файла, иначе файл не принимается
  (и старый недокачанный файл не докачивается вслепую).
- **«Загрузка прервана» вместо попытки запустить битую модель:** если сервер
  отдал меньше байт, чем заявил, файл удаляется и показывается ошибка
  «Загрузка прервана: <файл> — получено X из Y байт». Проверки готовности
  моделей по-прежнему сравнивают точные размеры, поэтому недокачанный файл
  не может попасть в распознавание.
- **Докачка сохранена:** обрыв соединения продолжается с места обрыва
  (`Range`, ответ `206`), при `200` файл скачивается заново. `Content-Range`
  обязан начинаться с нашего смещения и присылать ровно недостающие байты
  (`Content-Length` тела = заявленный размер минус уже скачанное).

## Что нового в v1.6.16

- **Русская модель GigaAM v3 вынесена в папку офлайн-моделей**
  `models/offline/ru` (раньше лежала в `models/streaming/ru`, хотя потоковой не
  является). Для ZH и LID остались `models/streaming/zh` и `models/streaming/lid`.
- **Проверенный источник:** `Smirnov75/GigaAM-v3-sherpa-onnx`, вариант
  `e2e_rnnt` int8 (`gigaam_v3_e2e_rnnt_encoder_int8.onnx` 304 МиБ, decoder,

- **Миграция:** старая папка `models/streaming/ru` удаляется при первом запуске,
  русскую модель (~326 МБ) нужно скачать заново; полный набор — ~454 МБ.

## Что нового в v1.6.15

- **Русское распознавание — на GigaAM v3** (`e2e_rnnt`, int8, sherpa-onnx
  `nemo_transducer`, `feature_dim = 64`). Модель e2e: пунктуация, заглавные
  буквы и нормализованные числа приходят прямо из распознавания, без
  постобработки. Используется в «только RU» и в «Авто», когда LID определил

  всего ~227 МБ.
- **LID в «Авто» стал быстрее**: окно анализа 0.8 с вместо 1.6–4 с,
  `numThreads = 2` у Whisper tiny (int8), повторные попытки — до 1.6 с.
- **LID получает только речь**: энергетический VAD с оценкой фонового шума
  запускает анализ лишь после начала реплики; тишина и гул в LID не уходят.

  подсказка с двумя рабочими вариантами хостинга. Выдуманный адрес
  `deepseek-translate.pages.dev` только сбивал с толку.
- **Режим `-Tunnel` проверен и не работает** (см. [docs/UPDATES.md](docs/UPDATES.md)):
  cloudflared регистрируется в Cloudflare, но публичный адрес отвечает 530.
  Для разных сетей остаётся статический хостинг.

## Что нового в v1.8

**Главное: китайская речь больше не принимается за русскую.**

Скриншоты показали корень проблемы. Распознаватель в режиме `ru-RU` **слышит**
китайский, но записывает его русскими буквами: «Нихао», «мехама». Проверка по
письменности видит кириллицу и считает это нормальным русским — поэтому язык
никогда не переключался, а в карточки попадала бессмыслица.

Отличить транслитерацию от настоящей речи по буквам нельзя, а модель — может.
Теперь в промпте авторежима два маркера:

| Маркер | Что значит | Что делает приложение |
|---|---|---|
| `[[!]]` | смысл транслитерации понятен, дальше идёт перевод | **фраза сохраняется** (Нихао → 你好), распознавание переключается на другой язык |
| `[[SKIP]]` | смысл непонятен | мусорная карточка убирается, распознавание переключается |

Маркеры не видны: пока текст — префикс маркера, ничего не показывается.
Появляется строка-подсказка «Похоже, говорили на 中文 — переключаю распознавание».

## Что нового в v1.5

### Авторежим: фразы больше не теряются

- **Кросс-языковой приём.** Если сеанс шёл на русском, а распознаватель вернул
  иероглифы, — фраза **принимается и переводится** как китайская, а не
  выбрасывается. Раньше такой результат просто терялся.
- **Быстрый зонд (0.7 с).** `onBeginningOfSpeech` → если за 700 мс не пришло ни
  одного частичного результата, язык сеанса почти наверняка не тот: сеанс
  перезапускается **внутри фразы** (`restartNow`), поэтому ловится хотя бы её
  продолжение, а не теряется целиком.
- **Переключение по паузам.** Тишина после принятой реплики один раз меняет
  ожидаемый язык — так первый же ответ второго собеседника попадает в нужный
  сеанс. Дребезга на паузах нет: флаг `lastSessionWasSilent`.

### Проверка обновлений (вариант А)

- Кнопка **«Проверить обновления»** в настройках + **автопроверка при запуске**
  (отключается тумблером).
- Адрес `version.json` правится прямо в приложении, без пересборки.
- Скачивание APK с прогрессом → `FileProvider` → системный установщик.
- Готовый бандл для хостинга — `dist/web/`, инструкция — [docs/UPDATES.md](docs/UPDATES.md).

## Что нового в v1.4

- **Починено качество распознавания.** В v1.3 `EXTRA_LANGUAGE` был убран целиком
  ради автоопределения — на устройствах без поддержки детекта это ломало
  распознавание («привет» → «.»). Теперь `EXTRA_LANGUAGE` передаётся всегда,
  а детект и переключение остаются как бонус, если распознаватель их умеет.
- **Авторежим переписан на чередование с проверкой.** Работает даже там, где
  автоопределения нет:
  - сеанс идёт на текущем языке;
  - если текст пришёл на этом языке (`LangDetect.matches`) — реплика принята,
    **язык не меняется**, поэтому один человек может говорить сколько угодно
    фраз подряд;
  - если распознаватель **услышал речь** (`onBeginningOfSpeech`), но текст
    вышел на другом языке или не вышел вовсе — значит, заговорил второй
    собеседник: мусорный черновик отбрасывается, следующий сеанс идёт на
    другом языке;
  - тишина в комнате язык НЕ переключает.
- **Фильтр мусора.** Реплики без букв («.», «…») больше не уходят в перевод,
  а «чужая» письменность (иероглифы при русском сеансе и наоборот) отсекается.
- Ручные режимы `🇷🇺 только RU` / `🇨🇳 только ZH` остаются как аварийный вариант.

### Ограничение

Если распознаватель устройства не поддерживает `EXTRA_ENABLE_LANGUAGE_DETECTION`,
полностью «бесшовное» определение невозможно: при смене говорящего теряется
первый короткий фрагмент его фразы — распознаватель «поймёт» это только по
факту речи на другом языке и переключится на следующем сеансе.

## Что нового в v1.3

- **Убрано «пиликанье» микрофона.** На время прослушивания глушатся
  `STREAM_SYSTEM`, `STREAM_NOTIFICATION` и `STREAM_MUSIC` (системный «динь»
  распознавателя), музыка поднимается обратно прямо перед TTS. Добавлено
  разрешение `MODIFY_AUDIO_SETTINGS`.
- **Починено автоопределение языка.** Причина была в `EXTRA_LANGUAGE`: если он
  задан, распознаватель не определяет язык сам. Теперь в авторежиме он не
  передаётся вообще, включены `EXTRA_ENABLE_LANGUAGE_DETECTION` и
  `EXTRA_ENABLE_LANGUAGE_SWITCH` (`MAX_SWITCHES=100`).
- **Запись не рвётся.** Пауза перед перезапуском сеанса в авторежиме = 0 мс,
  сеансы удлинены (тишина 2.5–3 с), поэтому паузы внутри разговора больше не
  рассекают фразу.
- **Никаких предположений о следующем говорящем.** Язык сеанса больше не
  переключается «на второго собеседника»: на Android 14+ решает распознаватель,
  на старых версиях язык подтягивается к последней реплике.
- **Аварийный ручной переключатель** на экране «Авто»: `Авто` / `🇷🇺 только RU` /
  `🇨🇳 только ZH` — на случай, если распознаватель устройства не умеет автоопределение.

## Что нового в v1.2

- **«Два экрана»:** перевод показывается собеседнику на его половине
  (`SideState.incoming`), а не на стороне говорящего. Половина показывает либо
  свою распознаваемую речь, либо перевод чужой фразы + её оригинал мелким шрифтом.
- **«Авто»:** убраны постоянные перезапуски распознавателя. Один сеанс записи,
  переключение языка внутри сеанса через `EXTRA_ENABLE_LANGUAGE_SWITCH` и
  определение через `SpeechRecognizer.DETECTED_LANGUAGE` (API 34+).
- **«Авто»:** убрана логика «следующая реплика — от второго собеседника».
  Язык следующего сеанса = язык последнего говорящего, поэтому один человек
  может говорить несколько раз подряд.

## Что было в v1.1

- **Запись больше не зацикливается.** Микрофон глушится *до* старта перевода:
  в режимах «Два экрана» и «Текст» распознавание останавливается сразу после
  финальной фразы (`stopAfterFinal`), только потом идёт перевод и озвучка.
- **Воспроизведение приостанавливает запись.** `SpeechController.speak()` переводит
  распознавание в паузу и возобновляет его по событию `onDone` от TTS —
  приложение не слышит само себя. Работает и в «Авто» при нажатии кнопки прослушивания.
- **Защита от дублей.** Одинаковая финальная фраза, пришедшая повторно в течение 4 секунд,
  не создаёт новую карточку и не запускает перевод заново.
- **API-ключ больше не вшит в код.** С v1.6.14 ключ вводится в окне
  «Ключ DeepSeek API» и хранится только на устройстве (`Prefs.apiKey`).

## Сборка

Нужен **JDK 17**: с Java 25 из Android Studio сборка падает, а портативный JDK уже
лежит в проекте — `.tooling/jdk17/`.

Сначала бинарные зависимости (AAR sherpa-onnx 47.8 МБ не лежит в репозитории):
скрипт `tools/fetch-deps.mjs` качает `app/libs/sherpa-onnx-1.13.8.aar`,
докачивая после обрыва.

```powershell
node tools\fetch-deps.mjs

$env:ANDROID_HOME="D:\Android\Sdk"
$env:JAVA_HOME="$PWD\.tooling\jdk17\<распакованная-папка>"
$env:GRADLE_USER_HOME="$PWD\.tooling\gradle-home"
.\gradlew.bat assembleRelease
```

APK: `app\build\outputs\apk\release\app-release.apk` (готовые копии — `dist\`).
Подпись — релизный ключ из `keystore.properties`. Выпуск обновления — `docs/UPDATES.md`.

## Безопасность

Ключ DeepSeek `sk-...` **не входит в APK** (с 1.6.14): он вводится пользователем
и хранится в `SharedPreferences` приложения без шифрования. Для личного
устройства это приемлемо; если APK или устройство попадёт к другим людям —
отзовите ключ на https://platform.deepseek.com/api_keys.
